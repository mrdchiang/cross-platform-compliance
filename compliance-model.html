Tier 1 · Endpointsenforce policy natively▼ expand
Three platform components, one policy model. Each enforces the same compliance baseline with its native tooling.
Windows — Autopilot provision · Intune manage · Defender EDR · BitLocker · Entra + WHfB (TPM).
macOS — ABM + DEP provision · Iru/Kandji manage · XProtect + cloud EDR · FileVault · Entra + Secure Enclave.
Linux — cloud-init / autoinstall · management framework = BUILD · EDR + SELinux · LUKS · HW-bound auth = OPEN.
The Linux management framework is the mandate in the JD — there is no native Linux MDM, so this is the build-gap.
◆ Decision · Visibilityhow do we see all three?▼ expand
You need endpoint state across Windows, macOS, and Linux. Normalizing three logging schemas is a trap. Decision: use one read-only verification layer.
Call: osquery × Fleet (REQUIRED) — one SQL query language across all three. Read-only by design = trustworthy.
Gives Linux visibility with no MDM required — the single strongest answer to the Linux gap.
Why not native logs: Windows Event Log, macOS Unified Logging, and journald have different schemas — normalizing them is an endless project. osquery asks the same question everywhere.
Tier 2 · Verificationosquery · Fleet▼ expand
Read-only SQL over endpoint state — encryption, EDR present, lock config, software inventory, patch state. Same checks on all three platforms.
Deploys via Fleet (open-source management of osquery). The verification layer the whole model sits on.
You can query: is disk encryption on? is the EDR agent running? is the screen lock set? what software is installed? is this host patched?
Tier 3 · Four Drift Vectorswhat the model watches▼ expand
Four cross-platform signals that define "compliant" — and drift from baseline is the thing you catch.
Configuration — encryption, lock, EDR running, baseline state.
SaaS / Entra — Intune / Conditional Access policy drift.
Process / Change — was the change approved? no-CAB? colluding admins?
Vulnerability — Action1 patch state, CVE / KEV tracking.
◆ Decision · Endpoint backupline item — possibly deliberately no▼ expand
The decisions-first point: every line item is a decision, and "no" with a documented reason is valid. Endpoint backup is the proof.
Call: likely DELIBERATELY NO (or scoped) for a dev/IP estate.
Dev systems are reproducible — rebuild from source control + provisioning. The data that matters lives in version control and central storage, not on the laptop.
IP risk: backing up design data duplicates it onto backup systems you control less tightly.
Covers Code42 → Druva migration signal too — if they don't want endpoint backup, the Linux backup gap matters less than Linux visibility + reproducibility.
Tier 4 · Compliance Enginedrift → remediate → change → report▼ expand
Aggregates the four vectors into a single defended posture number. Auto-remediates approved drift, enforces change control, generates evidence.
Auto-remediation — drift → fix → verify → escalate (closes the loop).
Change control — request → approve → execute; no admin acts alone (the 8 multi-admin controls).
Audit evidence — CMMC / board / auditor reports in hours, not weeks.
This is the layer that makes posture mean something to an auditor.
